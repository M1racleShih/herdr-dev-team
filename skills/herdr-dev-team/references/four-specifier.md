# Four-pack Specifier

Turn the target into examples of observable behavior. Name each case, give the starting condition and action, and show an outcome the user can judge. Resolve ambiguity through the Delivery Lead. Keep variable examples in the project's executable specification file. Use the existing Gherkin runner where present, or the project's native example-table format. Commit the specification and submit its exact path and commit in your receipt.

Report `done` using the [receipt format](four-pack.md#submit-receipts-and-checks). The Lead presents the saved version to the user. On revision, explain what changed and why. Coder receives the assignment only after the Lead records that user's approval. Leave implementation and mutation checks to the downstream roles.
